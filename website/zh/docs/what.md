# ZryxOS 是什么

![ZryxOS 架构](/architecture.svg)

ZryxOS 是基于 **JDK 21** 和 **Spring Boot 3.x** 构建的 Java 原生 Agent 操作系统。专为需要**私有部署、完全可审计、完全可控**的企业场景设计。

## 为什么需要 ZryxOS

ZryxOS 的愿景是让 Agent 部署在企业 Java 环境中**开箱即用**。虽然 Agent 生态已围绕 Python 框架和云托管平台成熟，但对于以下企业来说存在明显空白：

- 后端标准是 Java
- 出于合规和数据主权需要私有部署
- 需要 LLM 调用和工具执行的完整审计能力
- 希望核心逻辑可控，不被外部框架锁定

ZryxOS 填补这一空白，成为生态中首个 Java 原生 Agent OS。

## 核心定位

**Agent Runtime vs Agent OS**

- **Agent Runtime** — 执行单个 Agent：调用 LLM、执行工具、管理上下文、控制推理循环
- **Agent OS** — 管理一群 Agent：生命周期、统一渠道、共享记忆、多租户、治理，以及分布式模式下的跨节点协作

ZryxOS 是后者。它不是又一个 Agent，而是让一群 Agent 可靠运行和协同的运行底座。

## 设计理念

### 配置即 Agent

一份 Profile 配置定义一个 Agent。无需编写代码。多个 Agent 可在同一运行实例上并存，各自拥有隔离的配置。

### 自实现 ReAct

核心推理循环从头实现，不封装外部 Agent 框架。这赋予对执行流程和工具编排的完全控制。

### Java 原生

基于 JDK 21 和 Spring Boot 3.x 构建。单可执行 JAR 部署。复用现有 Java 运维工具链。运行在 K8s、虚拟机或物理机上——无云厂商锁定。

### 私有且可审计

部署在您自己的基础设施中。数据永不离开您的域。所有 LLM 调用和工具执行从第一天起就记录到 SQLite 审计表。

### 对接开放标准

- **工具** — MCP (Model Context Protocol)
- **Agent 协作** — A2A (Agent-to-Agent)
- **技能** — SKILL.md 格式

与生态系统集成，无专有协议。

## 五大核心能力

### 1. LLM 集成

基于 **Spring AI Alibaba** 的统一 Provider 抽象。支持主流模型：DeepSeek、通义千问、Kimi、OpenAI 和本地推理。运行时切换 Provider，无需更改代码。

### 2. ReAct 循环

推理引擎。LLM 决定是否调用工具以及调用哪些工具。ZryxOS 执行后回填结果。LLM 决定下一步，直到返回最终响应或达到最大迭代限制。循环行为完全可控。

### 3. 记忆系统

Agent 跨对话保留状态。两层记忆：会话记忆 + 长期记忆（MEMORY.md）。长期记忆使用基于文件的存储和关键词检索，预留向量检索升级路径。

### 4. 工具体系

Agent 通过工具与外部世界交互。内置工具：file、shell、HTTP。三档插件集成：

- **零代码** — 编写 SKILL.md，复用现有 MCP 服务器
- **轻代码** — 用任意语言实现自己的 MCP 服务器
- **重代码** — Java `@Tool` 注解的 Spring Bean

### 5. 对外服务

所有能力通过 REST API 暴露。10 个核心端点，用于会话管理、Agent 调用、记忆查询和系统信息。任何语言都可通过 HTTP 集成。

## 核心特性

- 🤖 **配置驱动** — 一份 Profile 定义一个 Agent，无需编码
- ☕ **Java 原生** — JDK 21 + Spring Boot，单 JAR 部署
- 🔒 **私有部署** — 运行在您的 K8s、虚拟机或物理机上。数据留在您的域内。
- 🛡️ **安全可审计** — 工具沙箱、白名单强制执行、从第一天起的完整审计轨迹
- 🧠 **自实现 ReAct** — 核心推理循环完全可控
- 🔌 **对接开放标准** — 工具用 MCP、Agent 协作用 A2A、技能用 SKILL.md
- 🧩 **三档工具扩展** — 零代码 → 轻代码 → 重代码，按复杂度选择
- 💾 **跨对话记忆** — 会话 + 长期记忆层
- 🌐 **无状态可扩展** — 运行实例无状态，状态外置，为分布式未来做准备

## 路线图

我们的开发理念是：**慢就是快，聚焦且克制**。首先，把单机运行时内核做扎实——让在一个节点上运行和管理一群 Agent 真正可用，被真实团队使用。然后在此基础上生长出分布式能力。分布式是终态愿景，但工程上坚持单机先行，每一步都走扎实。

- **阶段一（当前）— 单机运行时内核**
  - 五大核心能力跑通：配置驱动 Agent、多 Agent 并存、REST API 接入、MCP 集成
  - 让在单节点上运行和管理一群 Agent 真正可用
  
- **阶段二（规划）— 底座分布式**
  - 节点无状态化、状态外置、多副本部署
  - 支撑更大规模与高可用
  
- **阶段三（愿景）— 跨节点 Agent 协作**
  - 引入 Agent 通信底座，对接 A2A
  - 让不同节点上的 Agent 跨节点发现、委托、可靠异步协同
  
- **横向能力（伴随各阶段逐步补齐）**
  - 多租户、SSO、完整审计、工具策略、可观测、Web 管理界面
